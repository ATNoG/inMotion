## Implementation 1: TS-JEPA — Time Series Joint Embedding Predictive Architecture

### Papers
| Paper | Link | Key Content |
|---|---|---|
| Joint Embeddings Go Temporal (TS-JEPA) | `arxiv.org/abs/2509.25449` | Primary reference. NeurIPS 2024 Workshop. Architecture, masking, EMA, pretraining recipe. |
| I-JEPA (Assran et al., 2023) | `arxiv.org/abs/2301.08243` | Original JEPA for images. Conceptual foundation — multi-block masking, EMA target encoder, predictor design. |
| V-JEPA (Bardes et al., 2024) | `arxiv.org/abs/2404.08435` | Video JEPA. Spatiotemporal masking strategy relevant to multi-channel time series. |
| Official TS-JEPA Code | `github.com/Sennadir/TS_JEPA` | Reference implementation. Tokenizer (Conv1D patching), Transformer encoder, predictor, mask utils, EMA. |

### What It Is
SSL pretraining for time series. You mask parts of the sequence in **latent space** (not raw RSSI), and train the model to predict the masked embeddings from unmasked ones. The key insight: by predicting in latent space rather than reconstructing raw values, the model learns semantically meaningful representations that ignore noise/interference.

### Architecture
```
                     ┌──────────────┐
  RSSI (B,10,4) ─────┤   Tokenizer   ├──→ patches (B, N_patches, D)
                     │ Conv1D patching│
                     └──────────────┘
                            │
              ┌─────────────┴─────────────┐
              ▼                           ▼
     ┌────────────────┐          ┌────────────────┐
     │ Context Encoder │          │ Target Encoder  │
     │  (Transformer)  │          │  (Transformer)  │
     │  sees UNMASKED  │          │  sees ALL patches│
     │  patches only   │          │  weights via EMA │
     └───────┬────────┘          └───────┬────────┘
             │                           │
             ▼                           ▼
     ┌────────────────┐          ┌────────────────┐
     │   Predictor     │          │ target latents  │
     │  (Transformer)  │──────────▶   (masked only) │
     │  + mask tokens  │   L2 loss │                 │
     └────────────────┘          └────────────────┘
```

### Input & Masking Strategy
- **Tokenization**: Conv1D over 10-step sequence. With `kernel_size=3, stride=2` → 4 patches. Each patch covers ~2-3 timesteps.
  - Alternative for 10 steps: `kernel_size=2, stride=2` → 5 patches. Better resolution, more masking flexibility.
- **Masking**: Random block masking, 40–60% of patches. Mask contiguous blocks (2 patches) to force the model to infer missing temporal segments.
  - With 5 patches: mask 2–3 contiguous patches, predict them from the remaining 2–3.
  - The mask is applied AFTER tokenization (in latent space), not on raw input.
- **Multi-channel handling**: Each engineered channel gets its own tokenizer, or channels are concatenated before tokenization.
  - Option A: Tokenize each channel independently → 4 × 5 = 20 tokens. Mask across channels and time.
  - Option B: Concatenate channels → tokenize jointly → 5 tokens with 4×D features each. Simpler, loses cross-channel structure.

### Training Recipe
- **Phase 1 — SSL Pretraining** (on unlabeled data, can use test set too):
  - Context encoder: Transformer, 2 layers, d=128, 2 heads
  - Target encoder: same architecture, weights updated via EMA (momentum 0.996 → 1.0)
  - Predictor: Transformer, 2 layers, d=64 (smaller than encoder — bottleneck forces compression)
  - Loss: L2 between predicted and target latents at masked positions
  - Optimizer: AdamW, lr=1e-4, batch=128, epochs=200+
  - **Critical**: target encoder uses `stop_gradient` — no backprop through target branch
- **Phase 2 — Fine-tuning** (on labeled data):
  - Discard predictor, keep context encoder
  - Add classification head (Linear → 4 classes) on top of encoder output
  - Train with standard cross-entropy, your existing Trainer
  - Freeze encoder for first N epochs, then unfreeze

### Implementation Files to Create
- `dl/models/ts_jepa.py` — `TSJEPAEncoder`, `TSJEPAPredictor`, `TSJEPAPretrainer`
- `dl/jepa_training.py` — pretraining loop (separate from supervised Trainer)

### Key Hyperparameters to Tune
| Param | Range | Notes |
|---|---|---|
| `mask_ratio` | 0.3–0.7 | Higher = harder task, better representations if model can handle it |
| `ema_momentum` | 0.99–0.9999 | Higher = more stable targets, slower adaptation |
| `predictor_depth` | 1–3 | Shallower than encoder — bottleneck is key to JEPA |
| `patch_size` | 2–3 | Smaller = more patches, finer masking granularity |
| `pretrain_epochs` | 100–500 | More data (augmented) → more epochs |

### Expected Gain
- MCC improvement on **Noise** variant (currently 0.798) — SSL should learn interference-invariant features
- MCC on Normal may not beat DeepStack (0.859) but could approach 0.84 with single model
- Key win: **data efficiency** — pretraining uses unlabeled data (test set sequences without labels)

## Implementation 2: T-JEPA — Tabular JEPA with Feature Masking

### Papers
| Paper | Link | Key Content |
|---|---|---|
| T-JEPA (Thimonier et al., 2024) | `arxiv.org/abs/2410.05016` | Primary reference. Feature-level masking, regularization tokens, collapse prevention. |
| I-JEPA (Assran et al., 2023) | `arxiv.org/abs/2301.08243` | Conceptual foundation. |
| SubTab (Ucar et al., 2021) | `arxiv.org/abs/2105.14240` | Predecessor — feature subset masking in raw data space. T-JEPA does this in latent space. |
| SCARF (Bahri et al., 2022) | `arxiv.org/abs/2106.13008` | Contrastive SSL for tabular data. Baseline to compare against. |

### What It Is
Treat each of your 10 timesteps as a "feature" (column) in a tabular dataset. Mask a random subset of timesteps, encode the unmasked ones, and predict the latent representations of the masked ones. **Augmentation-free** — no need for synthetic Gaussian noise or Mixup, which you showed can hurt recurrent models.

The key innovation: **regularization tokens [REG]** — learned tokens appended to the input that prevent representation collapse by acting as a "pressure release valve" for excess information.

### Architecture
```
  RSSI (B, 10) flattened ──→ Embedding Layer (each timestep → d-dim)
                                      │
                    ┌─────────────────┤
                    ▼                 ▼
           ┌──────────────┐   ┌──────────────┐
           │Context Encoder│   │Target Encoder │
           │ (Transformer) │   │ (Transformer) │
           │ + [REG] token │   │ no masking    │
           │ sees UNMASKED │   │ EMA weights   │
           │ timesteps only│   │               │
           └──────┬───────┘   └──────┬────────┘
                  │                  │
                  ▼                  ▼
           ┌──────────────┐   ┌──────────────┐
           │  Predictor    │──▶│target latents │
           │ (Transformer) │   │(masked feats) │
           │ + mask tokens │   │               │
           └──────────────┘   └──────────────┘
                  L2 loss
```

### Input & Masking Strategy
- **Input shape**: (B, 10, 4) → flatten per channel? Or treat each (timestep, channel) as a feature → 40 "features".
  - **Option A** (simpler): Per-channel T-JEPA. Run 4 independent T-JEPAs (one per engineered channel), concatenate latents. Input: (B, 10) each.
  - **Option B** (richer): Joint T-JEPA. 40 features total. Mask across both time and channels → model learns cross-channel structure.
- **Masking**: Per-sample, randomly mask 30–50% of features. Non-overlapping context and target masks.
  - Unlike TS-JEPA (block masking), T-JEPA uses **independent per-feature masking** — any timestep can be masked individually.
  - Mandatory: at least 1 timestep per "region" (early/mid/late) must be unmasked in context.
- **[REG] token**: Appended to context input; never masked. Discarded during fine-tuning. Dimension = same as feature embeddings (d).

### Training Recipe
- **Phase 1 — SSL Pretraining**:
  - Embedding: Linear(4 → d) per timestep-position or Linear(1 → d) per feature
  - Context encoder: Transformer, 2-3 layers, d=128, 4 heads
  - Target encoder: same architecture, EMA (momentum 0.996)
  - Predictor: Transformer, 2 layers, d=64 (bottleneck)
  - [REG] token: 1–4 learnable tokens, initialized randomly
  - Loss: L2 between predicted and target latents at masked feature positions
  - **Critical difference from TS-JEPA**: masking is per-feature, not per-block. This tests whether the model can infer individual missing RSSI values from surrounding timesteps — exactly the interference-robustness skill.
- **Phase 2 — Fine-tuning**: Same as TS-JEPA. Discard predictor + [REG] tokens, add classifier head.

### Implementation Files to Create
- `dl/models/t_jepa.py` — `T JEPAEncoder`, `T JEPAPredictor`, `RegularizationTokens`

### Key Hyperparameters to Tune
| Param | Range | Notes |
|---|---|---|
| `mask_ratio` | 0.3–0.5 | Per-feature, independent |
| `num_reg_tokens` | 1–8 | More tokens = stronger collapse prevention, but may "absorb" useful info |
| `ema_momentum` | 0.99–0.9999 | Standard JEPA range |
| `feature_grouping` | per-timestep vs per-channel | Architectural choice with big impact |

### Expected Gain
- Better than TS-JEPA on **short-range interference patterns** (single-timestep spikes from concurrent devices)
- Per-feature masking forces the model to learn local interpolation — directly useful for denoising interfered RSSI
- Augmentation-free — avoids the regressions you saw with recurrents on synthetic data

## Implementation 3: LeWM SIGReg — Gaussian Latent Regularizer

### Papers
| Paper | Link | Key Content |
|---|---|---|
| LeWorldModel (Maes et al., 2026) | `arxiv.org/abs/2603.19312` | Primary reference. SIGReg formulation, two-loss training, collapse prevention. LeCun's group (Mila/NYU/Brown). |
| LeJEPA (Maes et al., 2025) | `arxiv.org/abs/2511.08544` | Predecessor. Detailed derivation of SIGReg, theoretical justification, ablation studies. |
| VICReg (Bardes et al., 2022) | `arxiv.org/abs/2105.04906` | Related regularizer — variance-invariance-covariance. SIGReg is simpler (Gaussian prior only). |
| Barlow Twins (Zbontar et al., 2021) | `arxiv.org/abs/2103.03231` | Alternative collapse-prevention method. Compare against. |

### What It Is
NOT a new model. A **regularization technique** that replaces your current stack of L1 + L2 weight decay + dropout (0.3) + label smoothing (0.1) + Mixup (α=0.2) with a single term: **SIGReg**, which enforces a Gaussian distribution on the latent space.

The claim (from LeWM paper): this single regularizer prevents representation collapse in JEPA training, replacing what previously required 6 loss terms. For your supervised setting, the hypothesis is: Gaussian-regularized latent spaces produce more separable, better-calibrated features.

### Mathematical Formulation
```
L_total = L_ce(y, ŷ) + λ · SIGReg(Z)

SIGReg(Z) = D_KL( P(Z) || N(0, I) )
           = ∫ p(z) log(p(z)/q(z)) dz

where Z = encoder(x) ∈ R^d,  P(Z) = empirical distribution of latents
```

In practice, this is implemented as a **maximum mean discrepancy (MMD)** or **moment-matching** loss between the batch of latent vectors and samples from N(0, I):
```
SIGReg(Z) = ||μ(Z)||² + ||σ(Z) - 1||²   (match first two moments)
```
or
```
SIGReg(Z) = MMD²(Z, N(0,I))   (kernel-based distribution matching)
```

### How to Apply to Your Pipeline
- **Step 1**: Pick your best single model (CNN, MCC 0.838). Add a latent bottleneck layer before the classifier: `Linear(hidden_dim, latent_dim)` where `latent_dim = 64` or `128`.
- **Step 2**: Remove from config: `l1_lambda=0`, `weight_decay=0`, `dropout=0`, `label_smoothing=0`, `use_mixup=False`.
- **Step 3**: Add to loss: `total_loss = cross_entropy + λ * sigreg_loss(latent_vectors)`
- **Step 4**: Tune `λ` (start at 0.01, range 0.001–0.1) and `latent_dim` (64, 128, 256).

### Implementation Files to Create
- `dl/sigreg.py` — `SIGReg` loss module (MMD-based and moment-matching variants)
- Modify `dl/training.py` — add `sigreg_lambda` to config, compute SIGReg in training step

### Key Hyperparameters to Tune
| Param | Range | Notes |
|---|---|---|
| `sigreg_lambda` | 0.001–0.5 | Too high = latents become pure Gaussian noise, lose class structure |
| `latent_dim` | 32–256 | LeWM uses 192. Smaller = stronger regularization (harder to be Gaussian in low dim) |
| `sigreg_mode` | `mmd` vs `moments` | MMD is more expensive but more principled. Moments is cheap. |
| `mmd_kernel` | RBF, linear, mix | RBF with multiple bandwidths is standard |

### Expected Gain
- **If it works**: Comparable or slightly better MCC than the full regularization stack, with dramatically simpler training (fewer hyperparameters, no augmentation needed)
- **If it doesn't**: MCC drops because SIGReg alone can't replace the inductive biases of Mixup + dropout for small datasets
- **Key risk**: SIGReg was designed for world-model latent spaces (192-dim embeddings of images), not 4-class classification logits. The regularizer may be too weak for the classification head's low-dimensional space.

## Implementation 4: Mamba-3 Hybrid Architectures

### Papers
| Paper | Link | Key Content |
|---|---|---|
| Mamba-3 (Lahoti et al., 2026) | `arxiv.org/abs/2603.15569` | Primary. Exp-trapezoidal discretization, complex state, MIMO. CMU/Princeton/Cartesia. |
| Mamba-2 (Dao & Gu, 2024) | `arxiv.org/abs/2405.21060` | Foundation. SSD framework, hardware-efficient SSM, the API you'll actually use. |
| Mamba-1 (Gu & Dao, 2023) | `arxiv.org/abs/2312.00752` | Original selective SSM. You already have this in `dl/models/mamba.py`. |
| TSCMamba (Ahamed & Cheng, 2024) | `arxiv.org/abs/2406.04419` | **Most relevant**. Multi-view + Mamba + tango scanning for TSC. 4-8% over TimesNet. |
| SST (Xu et al., 2024) | `arxiv.org/abs/2404.14757` | Mamba+Transformer hybrid for time series. CIKM 2025. Decomposition strategy, info interference finding. |
| Mamba-CNN Hybrid (Boukhari, 2025) | `arxiv.org/abs/2509.01431` | CNN + Mamba gating for vision. The gating pattern transfers to 1D. |
| ConvMambaNet | `emergentmind.com/topics/convmambanet` | CNN+SSM hybrid pattern. EEG/vision. |
| MambaMixer (2024) | `arxiv.org/abs/2403.19888` | SSM-based token + channel mixing. Alternative to attention. |

### What It Is
Four sub-variants of Mamba-3 hybrid architectures, progressing from simple to complex:

---

### 4a: Mamba-3 CNN (Simplest — Start Here)

**Input**: (B, 10, 4) engineered channels

```
  RSSI (B,10,4)
      │
      ▼
  ┌─────────────────────┐
  │  MultiScaleCNN       │  ← Your existing CNN (MCC 0.838)
  │  k=[3,5,7], residual │     Extract local temporal features
  │  out: (B, 10, 128)   │
  └─────────┬───────────┘
            │
            ▼
  ┌─────────────────────┐
  │  Mamba-3 Block ×2   │  ← NEW: replace GRU/LSTM/TCN
  │  d_model=128         │     Model sequence of CNN features
  │  d_state=16          │     Small state for short sequences
  │  MIMO heads=4        │     One head per engineered channel
  │  exp-trapezoidal     │     Better discretization
  └─────────┬───────────┘
            │
            ▼
  ┌─────────────────────┐
  │  AdaptiveAvgPool1d  │
  │  → Linear(128, 4)   │
  └─────────────────────┘
```

**Why this ordering**: CNN first extracts local patterns (slopes, edges in RSSI). Mamba-3 then models the *sequence* of CNN features — learning which temporal segments carry the discriminative signal (t=1-3 for initial position, t=4-6 for mid-trajectory transitions).

**Mamba-3 specifics for this variant**:
- `d_state=16`: Your sequences are 10 steps. The SSM state doesn't need to store much history.
- `MIMO heads=4`: Group the 128-dim hidden state into 4 groups of 32. Each group specializes to one aspect of the signal.
- `exp-trapezoidal`: The 𝛽 term (prev-timestep contribution) captures adjacent-step correlations — important for RSSI where step-to-step changes encode movement direction.
- **Skip complex state** for now: 10 steps is too short for rotational dynamics to matter.

### 4b: Mamba-3 + TCN (Convolutional SSM)

**Input**: (B, 10, 4)

```
  RSSI (B,10,4)
      │
      ├──────────────────┐
      ▼                  ▼
  ┌──────────┐    ┌──────────────┐
  │ TCN       │    │ Mamba-3 ×2  │
  │ dilations │    │ d_model=128  │
  │ [1,2,4,8] │    │ d_state=16   │
  │ out: 128  │    │ out: 128     │
  └─────┬─────┘    └──────┬───────┘
        │                 │
        └────────┬────────┘
                 ▼
          ┌─────────────┐
          │  Concat →   │
          │  Linear(256,4)│
          └─────────────┘
```

**Why TCN + Mamba in parallel**: TCN's dilated convolutions give exponentially growing receptive fields (covering 1, 2, 4, 8 steps) — naturally matched to 10-step sequences. Mamba-3 gives selective attention over the full sequence. The two views are complementary:
- TCN: fixed-pattern temporal convolution (hard-coded exponential receptive field)
- Mamba-3: data-dependent selective scanning (learns which timesteps matter per sample)

**Paper support**: SST (Xu et al.) found that decomposing signal into different "views" for Mamba vs. convolution avoids information interference.

---

### 4c: Mamba-3 + Transformer (State Space Transformer)

**Input**: (B, 10, 4)

```
  RSSI (B,10,4)
      │
      ▼
  ┌─────────────────────┐
  │  Positional Encoding │  ← Sin/Cos or learned
  └─────────┬───────────┘
            │
            ▼
  ┌─────────────────────────────────────────────┐
  │  Hybrid Block ×3                            │
  │  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
  │  │ Mamba-3  │→│ LayerNorm│→│Transformer│  │
  │  │ d=128    │  │          │  │ d=128     │  │
  │  │ state=16 │  │          │  │ heads=4   │  │
  │  └──────────┘  └──────────┘  └──────────┘  │
  │       ↑                           │         │
  │       └────── residual ───────────┘         │
  └─────────────────────────────────────────────┘
            │
            ▼
       Linear(128, 4)
```

**Critical finding from SST paper**: Naively interleaving Mamba and Transformer layers causes **information interference** — they encode/retrieve temporal information in conflicting ways. Solution from SST: **separate them by timescale**.

For your short sequences, the fix is simpler:
- Mamba-3 handles the **full sequence** (long-range: overall trajectory shape)
- Transformer with small window attention (window=3) handles **local context** (step-to-step transitions)
- This is implemented as Mamba → Transformer within each block (Mamba first compresses, Transformer refines locally)

### 4d: TSCMamba-Style Multi-View Mamba-3

**Input**: (B, 10, 1) raw RSSI + additional derived views

```
  Raw RSSI (B,10,1)
      │
      ├──────────────────┬──────────────────┐
      ▼                  ▼                  ▼
  ┌──────────┐    ┌──────────────┐   ┌──────────────┐
  │ ROCKET   │    │ CWT Spectral │   │ MLP Global   │
  │ random   │    │ (Morlet)     │   │ (1-layer)    │
  │ conv     │    │ 64×64 → 8×8  │   │ 10 → 128     │
  │ kernels  │    │ patches      │   │              │
  │ 10→5000  │    │ → 128        │   │              │
  │ →proj.   │    │              │   │              │
  │ →128     │    │              │   │              │
  └────┬─────┘    └──────┬───────┘   └──────┬───────┘
       │                 │                   │
       └─────────────────┼───────────────────┘
                         ▼
                  ┌─────────────┐
                  │ Switch Gate  │  ← learns which view(s) to use
                  │ (learnable)  │
                  └──────┬──────┘
                         ▼
                  ┌─────────────┐
                  │ Mamba-3 ×2  │
                  │ + Tango Scan│  ← forward + reverse sequence
                  │ d_model=256 │
                  └──────┬──────┘
                         ▼
                    Linear(256, 4)
```

**Tango Scanning** (from TSCMamba):
```python
def tango_scan(x, mamba_block):
    # x: (B, L, D)
    forward = mamba_block(x)           # L→R causal scan
    reverse = mamba_block(x.flip(1))   # R→L causal scan
    return forward + reverse.flip(1)    # element-wise sum
```

This gives you **inversion invariance**: a boarding pattern read backwards looks like alighting. The model learns that direction-reversed patterns are related, effectively doubling your data. For your specific case:
- AA reversed ≈ AA (symmetric)
- BB reversed ≈ BB (symmetric)
- AB reversed ≈ BA pattern shape (complementary!)
- BA reversed ≈ AB pattern shape

This is a powerful inductive bias for your 4-class problem.

**Switch gate**: A learnable scalar or small MLP that weights ROCKET vs. CWT vs. MLP features per sample. Allows the model to use spectral features for interfered samples and temporal features for clean ones.
